# 主观评测与人员质检报告口径

先给判断，再给数字和证据。所有统计来自过滤后的底层记录，正文用题目等权。不复用过去项目的模型名、分数、题号或人员名单。

## 主观报告

1. **整体结论**：先定义 A/B 与 G/B 方向，再给赢家、综合 GSB、G/B 明确胜率及百分点差；说明最大增益、相对短板和来源/时长/人员组方向。
2. **分维度结果**：表格展示维度、有效题数、G、As good、As bad、B 的加权数量与比例、Similar、GSB。解释主要与辅助增益、局部未同步提升。
3. **胜负因素**：比较题目等权 P(因素|G) 与 P(因素|B)，披露条件分母。多选条件率可超过 100%，不要把裸次数当作胜负分界。
4. **题型与场景边界**：按题号去重，披露每片题数；重叠切片不可相加。少于 10 题仅称趋势/风险信号/补题建议，较大样本也不能仅凭数量宣称统计显著。小样本负向信号应披露。
5. **版本画像与决策**：总结增益、短板、复验与进入下一轮的依据。只按证据下结论，不根据模型名称、训练阶段或预期推断。
6. **白盒 Badcase**：按照下方证据层级分析。
7. **稳定性**：记录原始和过滤后人数/票数/题数、过滤原因、行加权对照、逐人剔除敏感性、来源/时长/人员组方向、四档闭合及追溯一致性。

“明确胜率”仅使用 G 或 B。As bad 表示双方都有问题，不归为某一模型单独失败。条件率差与共现只能描述相关关系；视频复核或控制分析不足时用“可能联动”，不写确定因果。

## Badcase 证据层级

评价维度 → 该维度 B 票影响因素 → 已观看视频的细分问题 → 题目证据。

默认白盒题中 B票 > G票 为该维度相对败局。强败局使用本项目约定的阈值，结合有效票数解释，不把某个旧项目的固定票数阈值照搬。

只统计该维度 B 票的因素，每题归入最高频因素簇，并列可归入多簇；簇题数因此不可简单相加。每维展示 GSB、败局/强败局题数、败局 B 票数和待复核问题。每簇展示题数、因素在对应 B 票中的出现率、代表题及全部题号。

正文优先展示至少覆盖两题的因素簇，单题留在明细。回看每簇代表视频后才描述可见缺陷，至少两道已观看题支持才归纳跨题问题。题型标签描述任务类别，影响因素记录人员反馈，细分问题描述实际视频现象，三者不可互换。

没有因素字段时写“无法自动下钻，需人工回看”。未观看时只写“数据指向”或“建议核查”，不能根据 Prompt 编造缺陷。

## 人员报告

单独交付：总体结论、综合分及子指标、GT 逐题表现与覆盖、风险规则、强度偏差全量与分维结果、逐人剔除敏感性、过滤理由与校准建议。

共识率低不等于标错；必须剔除同时满足风险与实质影响。没有达到条件时保留人员并披露观察项，允许无人剔除。方向一致不能替代强度校准。

## 证据与公开版本

工作区明细每题保留题号、完整 Prompt、四档票数、影响因素和 A/B URL，保证报告可追溯。公开发布时去掉内部账号、人员、群组、路径、视频 URL、版本与真实结果；没有公开授权的样本不附到公开报告中。

当前 Skill 不包含执行脚本，报告只能陈述实际已计算或已复核的内容，不能声称未执行的自动化验证已完成。
