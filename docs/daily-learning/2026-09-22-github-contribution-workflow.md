# 2026-09-22｜GitHub 学习记录工作流

## 今天理解了什么

今天复盘了一个重要区别：GitHub 的 Contribution 记录的是符合平台规则的提交活动，不等于“每天自动制造几个 commit”。真正有价值的做法，是把当天真实发生的学习、实验、复盘或文档改进整理成可追溯的内容，再提交到默认分支。

## 为什么昨天没有提交

昨天完成的是知识库网站发布和展示修复，但没有新增一篇学习笔记，也没有配置自动化任务。因此仓库最后一次提交停留在 2026-09-20。以后如果当天有新的学习内容，应及时写入 `docs/daily-learning/`，并由 GitHub Actions 检查和发布。

## 可执行的每日流程

1. 记录当天真实学习主题。
2. 写下一个新概念、一个例子和一个仍然不清楚的问题。
3. 对知识库做一次小的、可审查的更新。
4. 运行构建检查。
5. 提交并推送到默认分支。

## 关于“每天 3 条”

Contribution 数量受 GitHub 的作者身份、邮箱关联、默认分支、提交时间和平台统计规则影响，无法诚实保证固定数量。也不应该用没有实际内容的空提交伪造活跃度。更稳妥的目标是：每天最多拆成三类真实记录——学习笔记、实践改动、复盘总结；当天没有对应内容时不强行提交。

## 下一步

可以增加一个自动化检查：每天提醒是否完成学习记录，并在有真实改动时自动构建和发布网站；自动化不代替学习内容本身。
