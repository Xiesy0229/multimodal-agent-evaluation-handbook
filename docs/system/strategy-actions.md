# Strategy / Policy 与三种行动

<span class="status validating">正在验证</span>

Strategy / Policy 是 Agent 的策略层。它不是一句输出，而是一套持续判断逻辑：根据当前观察、任务目标、历史状态、置信度、风险和可用能力，决定下一步行动。

## 策略层每次判断什么

1. 当前画面中是否出现了与 Task 相关的事件？
2. 证据是否足够，还是应该继续观察？
3. 此刻输出会帮助用户，还是造成打扰或误报？
4. 主 Agent 是否有能力直接完成？
5. 是否需要调用工具、后台模型或子 Agent？
6. 当前行动的延迟、成本和风险是否可接受？
7. 能力失败后应该重试、降级、转人工还是安全结束？

## Speak

主动向用户输出文本、语音、告警或解释。

评测重点：

- 是否在正确时间说；
- 内容是否与视觉证据一致；
- 是否清晰、简洁且适合风险等级；
- 是否重复输出或打断用户；
- 实际播报是否成功。

## Silence

暂不输出，但继续观察和更新内部状态。Silence 不是“什么都没发生”，它仍然需要有理由、有继续观察条件，并写入 Transcript。

评测重点：

- 无事件时是否安静；
- 证据不足时是否避免过早下结论；
- 高风险事件发生时是否错误沉默；
- 沉默多久后会重新判断。

## Delegate

把任务交给已经接入的工具、后台模型或子 Agent。

Delegate 需要提前配置：

- 可调用对象；
- 输入输出 Schema；
- 权限；
- 超时时间；
- 成本限制；
- 失败处理和重试规则。

模型不能调用一个系统里根本不存在的能力。如果主 Agent 和后台能力都无法完成，应进入 Fallback，而不是假装任务已经完成。

## Fallback

常见顺序是：

```text
重试
→ 更换工具或模型
→ 请求补充信息
→ 降低任务目标
→ 说明不确定性
→ 转交人工
→ 安全拒绝并结束
```

高风险多模态场景中，宁可明确“不确定并转人工”，也不能把未经确认的判断伪装成事实。
