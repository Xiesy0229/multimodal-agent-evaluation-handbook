# 我如何开展 T2V / T2AV 成对视频评测

我用成对盲评比较两个视频生成模型，关注四个问题：整体谁更好、优势体现在哪里、哪些场景仍有短板，以及人员筛查后结论是否稳定。我把流程整理成可复用的 Skill，辅助数据审计、候选抽样、统计和报告；GT 确认与视频复核保留人工判断。

本文整理自我的评测方法与交接材料，公开版本只保留通用流程，不包含内部人员、工作群、项目版本、视频地址或实际评测结果。它是方法展示，不代表已发布完整自动化系统。

## 1. 先明确任务与方向

T2V 指文本生成视频，T2AV 指文本生成音视频。这里讨论的是两个模型的四档主观比较；能力项 C/R/N 检查点评测应另行设计，不混用数据、GT 或人员筛查结论。

开始前先约定目标、题集、评价维度、人员组、模型 A/B 对应关系与标签含义。评价维度由实际任务确定，不预设一定是五维或六维；综合评价与各分维度分别统计。

本方法统一使用以下四档口径，实际源表若相反，先转换并记录映射：

| 标签 | 含义 |
| --- | --- |
| G / Good | 模型 B 明显更好 |
| As good | 两边都较好 |
| As bad | 两边都有明显问题 |
| B / Bad | 模型 A 明显更好 |

As good 与 As bad 都进入 Similar，但报告保留两者拆分。As bad 不能解释成某个模型单独失败。

## 2. 审计逐人逐题的原始记录

检查题号、Prompt、模型 A/B URL、人员、人员组、实际评价维度、四档答案、影响因素、来源与时长。对空值、非法标签、重复记录、每题人数和每人题数给出审计结果。

题号、Prompt 与两列 URL 必须同题对齐；白盒/黑盒、时长和题型从源字段确认，不能靠题号顺序推断。模型方向未确认前不输出胜负结论。

## 3. 生成候选，人工确认 GT

GT 是人工确认的参考答案。设实际评价维度数为 K，默认每维选强 G、强 B、Similar 各一题，共 3K 道候选；整套候选尽量同时覆盖 As good 与 As bad。

优先高共识题；缺少强共识时如实标注“本维最强”或“争议题”。同一原题不跨维重复入选，每题只确认目标维度。人员分属互斥题组时检查每人的候选覆盖量，尽量均衡。

候选统计不等于人工 GT。GT 未回收时只输出候选与审计信息，不发布正式人员剔除名单。

## 4. 把人员可靠性与评分强度分开检查

我结合 GT 一致性、留一同题共识、题内跨维独立性、标签多样性、维内跨题变化性与同组偏好检查人员风险。

还单独检查“同方向极端化”：某人可能方向经常一致，却频繁把接近档打成明显胜负档。因此输出个人强档率、同题同维同组强档率、两者差值、强度一致率与同方向过度强调率，并逐维检查，避免被总体平均掩盖。

人员风险不能直接等同于必须剔除。先做单人剔除敏感性分析，只有人员风险与项目约定的实质影响条件同时成立时，才确认剔除。允许一轮无人必须剔除。

完整指标和方法默认阈值见 [人员质检参考](https://github.com/Xiesy0229/multimodal-agent-evaluation-handbook/blob/main/skills/analyze-pairwise-video-evals/references/methodology.md)。

## 5. 从底层记录重算，保证每题等权

过滤确认剔除的人员后，从原始记录重新计算。对某一评价维度，若第 i 题剩余有效票数为 n_i，则该题每条票的权重为：

```text
w_ij = 1 / n_i
Similar = As good + As bad
GSB = (G + 0.5 × Similar) / (B + 0.5 × Similar)
```

每题总权重为 1；统计四档加权数量、百分比、Similar 和 GSB。GSB 大于 1 表示模型 B 占优，小于 1 表示模型 A 占优，等于 1 表示该口径下持平。

无有效票的题目单列并披露，不当作零票继续平均。分母为零时标注无穷或不可稳定计算，保留四档分布。行加权统计可以作为敏感性对照，正文使用题目等权结果。

## 6. 解释胜负与场景边界

整体结论之后展示完整分维度分布，再比较题目等权的 P(因素|G) 与 P(因素|B)，而非仅比较因素次数。多选因素的条件率之和可以超过 100%。

因素共现不证明因果。题型标签按题号去重，同题可属于多个切片，因此切片题数不可相加。披露每个切片的题数；少于 10 题时，本方法只作为趋势或补题信号。达到 10 题也不是统计显著性的保证。

## 7. Badcase 从反馈下钻到视频证据

先验证白盒题范围，再逐题逐维统计。默认 B 票多于 G 票作为该维度的相对败局，“强败局”阈值按项目有效票数约定。

下钻层级为：

**评价维度 → 该维度 B 票的影响因素 → 视频复核后的细分问题 → 题目证据**

因素聚类来自人员反馈，不能拿 Prompt 语义替代。并列最多因素允许一题进入多个簇。回看代表视频后，才写具体可见缺陷；至少两道已观看视频支持同类现象时，才总结为跨题问题，单题标为个例。无因素字段时明确需要人工回看。

## 8. 交付并核对一致性

| 交付物 | 用途 |
| --- | --- |
| GT 候选表 | 候选依据、目标维度、人员覆盖、人工答案栏 |
| 人员质检评分与独立报告 | 指标、风险、剔除敏感性、校准建议 |
| 主观评测报告 | 整体结论、分维度结果、归因、边界与决策 |
| 分析明细 | 等权汇总、场景切片、因素统计、题目证据 |
| 白盒追溯表（存在白盒时） | 题号、Prompt、两列 URL 与结果对应关系 |

交付前核对模型方向、GT 覆盖、四档数量与百分比闭合、每题权重、过滤前后样本量，以及报告与明细数字的一致性。原始工作簿保留，输出写入独立工作区。
