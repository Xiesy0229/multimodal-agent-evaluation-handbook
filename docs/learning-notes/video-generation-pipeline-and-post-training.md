# 视频生成模型完整链路与后训练术语梳理

> 适用场景：理解视频生成模型从数据准备、预训练、后训练到评测和上线的整体流程，定位偏好标注、RL 主观评测及人员质检工作的作用。
>
> 说明：不同团队的阶段命名、模型结构和执行顺序可能不同。本文采用常见口径，不代表某个团队的固定技术方案。

## 一、先看整体链路

**准备数据 → 预训练获得基础能力 → 后训练改善能力与偏好 → 蒸馏／系统优化降低成本并完善交付 → 评测验证 → 上线收集反馈 → 下一轮优化。**

这是一套反复迭代的闭环，而不是固定走完一次的流水线：

- 评测贯穿所有阶段，不只发生在上线前。
- 偏好对齐、蒸馏和质量微调可以调整顺序，也可以交替进行。
- 超分等模块可能独立训练，并在推理链路中运行。
- 不同问题需要回到不同环节，并非所有问题都应通过 RL 解决。

## 二、关键术语及其归属

后训练（Post-training）通常指：在已完成预训练的基础模型上继续训练，以改善能力、质量、偏好对齐或生成效率。它不是“上线后训练”，也不局限于 RL。

| 术语 | 全称／常见含义 | 主要作用 | 是否属于后训练 |
|---|---|---|---|
| SFT | Supervised Fine-Tuning，监督微调 | 用目标样本教模型如何生成 | 通常是典型后训练方法 |
| QT | 可能指 Quality Tuning，质量微调 | 改善生成质量的阶段或方案 | 若指基础模型的后续质量微调，通常是；需确认团队定义 |
| DPO | Direct Preference Optimization，直接偏好优化 | 利用优选／劣选结果对优化生成模型 | 通常是典型后训练方法 |
| RM | Reward Model，奖励模型 | 为生成结果提供奖励分数 | 通常是后训练体系的配套训练环节，训练的是奖励模型 |
| RL | Reinforcement Learning，强化学习 | 根据奖励反馈优化生成策略 | 用于基础模型的后续优化时属于后训练；RL 本身是通用框架 |
| PPO | Proximal Policy Optimization，近端策略优化 | 一种 RL 策略优化算法 | 用于后训练时属于后训练方法 |
| GRPO | Group Relative Policy Optimization，组相对策略优化 | 利用一组候选的相对奖励构造优化信号 | 用于后训练时属于后训练方法 |
| RLHF | Reinforcement Learning from Human Feedback | 利用人类反馈进行强化学习 | 通常属于后训练／对齐体系 |
| RLAIF | Reinforcement Learning from AI Feedback | 利用 AI 反馈进行强化学习 | 通常属于后训练／对齐体系 |
| DMD | Distribution Matching Distillation，分布匹配蒸馏 | 将多步生成模型蒸馏成少步模型 | 广义上可纳入后训练，也常单列为蒸馏／加速 |
| SR | Super-Resolution，超分辨率 | 提升图像／视频分辨率与细节 | 是任务／模块，不能直接判定；运行超分本身不是后训练 |
| Arena | 竞技场式对战评测 | 通过匿名成对比较评估模型偏好表现 | 不是训练，是评测机制 |
| GSB | Good／Similar／Bad，成对比较的常见称呼 | 判断版本相对表现是更好、相近还是更差 | 不是训练，是评测方式；具体方向定义依团队规范 |

### 术语使用边界

- QT 不是统一术语。本文暂按质量微调理解，不能直接认定 QT＝SFT。
- SR 在本文中指超分；若出现在其他训练报告里，需要结合原文确认。
- DMD 在本文中指生成模型领域的分布匹配蒸馏。
- PPO、GRPO 等在语言模型与视频扩散模型中的具体实现可能不同。
- 窄口径的后训练主要强调能力改善和偏好对齐；宽口径可能包含蒸馏等训练优化。

## 三、各阶段的工作内容

### 1. 数据准备：决定模型有机会学到什么

准备视频、文本描述、质量属性及合规来源信息，再进行清洗、去重、切片、描述生成和筛选。音视频模型还需要音频及音画对应信息。

例如，视频展示“一个人拿起杯子喝水”，文本描述就应准确对应动作，避免写成“放下杯子”。

**主要目标：数据准确、丰富，并覆盖目标能力。**

这一阶段也有标注和质检，但主要服务于训练数据建设，不是比较两个模型谁更好。

### 2. 预训练：获得基础生成能力

模型在大量数据上学习物体外观、文本与画面的对应关系、动作、镜头及时间变化。音视频模型还需学习声音及其与画面的关系。

产物是具备广泛基础能力的模型，但可能仍存在手部变形、动作不连贯、物体消失、指令遵循不足或音画不同步等问题。

**主要目标：获得基础能力，不保证每次输出都满足产品要求或人类偏好。**

### 3. 能力与质量微调：把基础能力打磨好

常见方法是 SFT；团队也可能把相关质量改善阶段称为 QT。

| 问题 | 可能准备的数据 | 期望改善 |
|---|---|---|
| 人物结构、手部或动作较差 | 动作清晰、结构正常的视频 | 动作与结构质量 |
| 不遵循复杂 Prompt | 描述准确、包含多个约束的样本 | 指令遵循 |
| 镜头表现单一 | 丰富的镜头运动样本 | 镜头控制 |
| 音画不同步 | 高质量同步音视频 | 音画对应关系 |

SFT 的基本形式是：**Prompt＋目标视频 → 学习生成目标内容。**

SFT 不只用于提升质量，也可以学习新任务、风格或控制方式。QT 则需要确认是阶段名称还是具体方案。

**主要目标：更稳定地做到指定任务。**

### 4. 偏好对齐：更倾向于人觉得好的结果

同一 Prompt 可以生成多个结果，偏好标注用于表达哪些结果更符合约定标准。

例如，A 画面精致但动作不自然，B 画面普通但动作完整。评审需要根据标准判断，而不能各自采用不同的质量取舍。

| 路线 | 数据如何使用 | 生成模型如何更新 |
|---|---|---|
| DPO | 使用经过质检的优选／劣选结果对 | 直接进行偏好优化 |
| 基于 RM 的 RL | 先用偏好数据训练奖励模型 | 生成结果、获得奖励，再用 RL 更新 |

典型 DPO 路线：

**生成候选 → 偏好比较 → 数据质检 → DPO 训练 → 新模型。**

典型的基于奖励模型的 RL 路线：

**生成候选 → 偏好比较 → 数据质检 → 训练 RM → RM 评价新生成结果 → RL 更新生成模型。**

RL 也可使用规则或其他奖励函数，不一定需要独立 RM。标准 DPO 不需要显式训练奖励模型，也不需要运行经典在线 RL 循环，但其推导与带参考模型约束的 RLHF 目标有关。

**主要目标：让生成倾向更符合定义的质量与偏好。**

风险：奖励高不一定等于人真正觉得好。如果奖励设计漏掉动作畸形等问题，优化过程可能提升分数，却没有改善实际体验。

### 5. 蒸馏与加速：平衡质量、速度和成本

高质量模型可能需要很多采样步骤，导致延迟和成本较高。DMD 等方法可让少步学生模型学习多步教师模型的生成分布。

例如，从 50 步减少到 4 步只是说明用途的示例，并非固定配置或效果承诺。

蒸馏后需要重新检查动作、细节、指令遵循、稳定性和多样性是否退化。

**主要目标：用更少步骤生成，并尽量保留质量。**

它不一定在偏好对齐之后，也可以先蒸馏，再对少步模型继续微调或偏好优化。

### 6. 生成系统与超分：形成最终交付内容

最终视频可能不仅来自主生成模型，还经过 SR、时序处理、音频合成、安全检测和编码压缩等环节。

例如：**主模型生成低分辨率视频 → SR 提升分辨率 → 编码输出。**

SR 主要改善分辨率与细节，不能可靠地修复动作逻辑或身体结构错误，也可能引入虚构细节、过度锐化或帧间闪烁。

**主要目标：满足交付规格、观感和服务要求。**

评测时应明确是在评主模型原始输出，还是完整系统最终输出。如果主模型和 SR 同时变化，不能将所有提升直接归因于主模型。

### 7. 评测与质检：验证变化是否有效

评测贯穿所有阶段，既要看质量，也要看效率、安全和可靠性。

| 评测类型 | 主要回答的问题 |
|---|---|
| 单视频分维度评价 | 动作、画质、指令遵循、音画同步等具体差在哪里 |
| GSB／A/B 成对比较 | 新版本相对旧版本更好、更差还是相近 |
| Arena | 在指定参赛模型与测试条件下，谁更受偏好 |
| 专项测试 | 手部、多人互动、复杂运动等能力是否改善 |
| 速度与成本测试 | 延迟、吞吐、显存和生成成本是否达标 |
| 安全评测 | 是否满足安全与合规要求 |

Arena 更强调对战与排名，GSB 常用于版本之间的成对比较；具体机制和命名依团队而定。排名受 Prompt 分布、评审标准、参赛模型和样本量影响，不是绝对能力值。

#### 区分训练数据与评测数据

- **训练用偏好数据**：用于 DPO，或用于训练 RM。
- **评测用偏好数据**：用于验证提升，应尽量独立于训练数据。

两者可能都采用 A／B／Similar，但用途不同。Similar 如何进入训练取决于具体方法，不能默认所有算法都直接使用它。

人员校准、多人同标、异常筛选及人工复审，是保证判断可靠的关键环节：

- 训练数据标错，可能给模型错误的学习方向。
- 评测数据标错，可能使团队误判版本好坏。
- RM 数据的系统性偏差，可能在后续 RL 中被放大。

### 8. 上线与反馈：进入下一轮优化

模型通过质量、安全、速度和成本检查后进入产品服务。真实用户可能带来测试集未覆盖的场景、复杂表达和偶发缺陷。

| 发现的问题 | 可能返回的环节 |
|---|---|
| 缺少某种基础能力 | 补充数据、继续预训练或针对性微调 |
| 已有能力不稳定 | SFT／质量微调 |
| 输出不符合偏好 | DPO、奖励设计或 RL |
| 生成慢、成本高 | 蒸馏、推理优化 |
| 分辨率与细节不足 | SR 或主模型质量优化 |
| 提升结论不可信 | 检查评测集、评审标准与标注质量 |

## 四、相近概念怎么区分

| 对比 | 核心区别 |
|---|---|
| SFT 与 DPO | SFT 学目标示例；DPO 学优选与劣选之间的偏好 |
| QT 与 SFT | QT 可能是质量改善阶段；SFT 是具体方法，二者不一定等同 |
| RM 与 RL | RM 负责打分；RL 利用奖励优化生成策略 |
| DPO 与基于 RM 的 RL | DPO 直接利用偏好对；后者先训练 RM，再通过奖励优化 |
| RL 与 PPO／GRPO | RL 是框架；PPO／GRPO 是具体更新算法 |
| RLHF 与 RLAIF | 强调反馈来源不同：人类与 AI |
| DMD 与 SR | DMD 主要减少生成步骤；SR 主要提升分辨率 |
| Arena 与 DPO | Arena 用偏好判断模型表现；DPO 用偏好更新模型 |

## 五、你当前工作的定位

如果你接触的是 RL 主观评测、成对视频比较和人员质检，工作通常主要落在两处，具体取决于数据用途：

1. **偏好训练数据建设**：影响模型往哪个方向学习。
2. **模型效果验证**：影响团队是否正确判断版本提升。

你会同时遇到 QT、DPO、RL、DMD、SR 和 Arena，是因为评测需要覆盖不同训练阶段、模型版本和系统模块的变化。

这不表示你直接参与了每一种训练算法，而是你的工作为训练和版本决策提供可靠的人类判断。

### 接到一个批次时，优先确认的问题

- 这批数据用于训练，还是用于评测？
- 比较的模型／版本分别是什么？改变了哪些模块？
- 评的是原始生成结果，还是含 SR 等处理的最终视频？
- 本轮重点评什么，综合偏好如何权衡？
- A／B／Similar 和 GSB 的方向如何定义？
- 标注数据最终进入 DPO、RM，还是只用于统计与版本决策？
- 训练集与评测集是否独立，人员是否经过校准？

## 六、一句话记忆

- **预训练：学习基础能力。**
- **SFT：照着示例学。**
- **QT：改善质量的阶段或方案，具体定义待确认。**
- **DPO：根据好坏对比学。**
- **RM：给结果打分。**
- **RL：根据奖励调整生成策略。**
- **DMD：蒸馏成少步生成。**
- **SR：提升分辨率与细节。**
- **Arena／GSB：通过比较验证效果。**
- **质检：保证训练信号与评测结论可靠。**

**总结：这些内容属于模型后训练及其配套交付流程，但不全是后训练本身。评测与质检连接了模型优化、人类偏好和产品决策。**
